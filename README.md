# 戏墨彩 SC · Xi Mo Cai SC

一款基于**思源宋体 CN** 改造的**扁方重彩**中文字体，单字重。
**SIL Open Font License 1.1，免费商用。**

本仓库同时是这款字体的**落地页**（GitHub Pages）与网页字体分发点。

姊妹字体：[戏墨宋 SC](https://github.com/okko10086/ximosong)（四字重宋体）、
[戏墨黑 SC](https://github.com/okko10086/ximohei)（六字重黑体）。

---

## 先说清楚它是什么

**这是宋体的一个变体，不是新书体。**

它不是隶书、不是楷书、不是魏碑，也无意冒充任何一种书法字体。
它只做一件事：**在宋体的骨架上重新分配墨量**。

| 做了什么 | 幅度 |
|---|---|
| 整体压扁 | −12% |
| 横画加粗 | +85% |
| 竖画减细 | −14% |
| 横画走向起伏 | 小幅正弦调制 |
| 笔画端部外扩 | 端部附近宽度渐变 |

结果是一款**扁方、横重、对比强烈**的宋体 —— 适合标题、封面、招牌这类
需要「压得住」的场合。正文长文会因为横画偏重而略显沉。

**边界**：字的结构完全来自思源宋体，本字体只改厚度分布与走向。
骨架分析是全自动的，它能保证「不变形」，但**不能产生新的书写性** ——
笔画之间的呼应、起收笔的笔势，这些是手工设计才有的东西。

## 技术路线

### 试过并放弃的方案：拆笔画重画

最初的思路是把字形拆成一根根独立笔画，再按目标特征分别重画。

**这条路走不通。** 骨架分解对**粗细不均**的笔画会产生**平行重分支**：
实测「同」的「冂」被拆成 3 条互相重叠的路径，重画后各自外扩，叠成实心块或裂成碎片。

实测后果：92 个随机常用字里，**字怀个数的中位数变成源字的 2.00 倍**——
笔画被切碎。可读，但一眼就能看出是坏的。

### 现在的方案：拓扑不动，只推点

原字形的算子序列（`moveTo` / `lineTo` / `curveTo` / `qCurveTo`）**原样保留**，
只把每个点（含控制点）沿它到骨架的法线方向推开：

```
P' = P + n̂ · sign · (w_new − w_old)
```

位移等于**局部厚度的变化量**，有界，且不改变点原有的偏心量——衬线与末端形态因此得以保留。

**轮廓数不变、绕向不变、连通性不变 —— 结构上不可能碎裂。**

> 中间写过一版错的：`P' = S + n̂·sign·w_new`，那是把点**重新投影**到新半径上。
> 衬线尖端、笔画末端本来就离骨架更远，被硬拉回来就全毁了（「山」「气」「象」实测报废）。
> 改成「只施加变化量」才对。

### 两处保护

骨架分析有两个坑，各用一个措施兜住：

**① 交点附近衰减** —— 多笔交汇处「局部厚度」本身是个含混的量，在那里改厚度必然扭曲形状。
以交点为源做一次 BFS，把增益在交点附近衰减回 1.0，离开交点再恢复全量。

| `junc_span` | 字怀保持率 |
|---|---|
| 0（不衰减） | 83.8% |
| 0.055 | 87.2% |
| 0.120 | 91.9% |
| 0.220 | 92.6% |

**② 端点过滤** —— 骨架里的端点远多于笔画末梢。实测「海」有 **31 个端点、51 个交点**，
而真实笔画末梢约 10 个；其余是衬线外扩、宽度突变分叉出的**短枝假端点**。
端部处理若加在这些假端点上，就是在笔画中段平白鼓起一块。

判据：真末梢到最近交点的沿线距离应当足够长。加上这一层后，可以把 `junc_span`
从 0.220 降回 0.055（**重彩感更足**）而质量几乎不降：

| 配置 | 字怀保持率 |
|---|---|
| `junc_span=0.220`（无过滤） | 92.6% |
| **`junc_span=0.055` + `tip_ratio=0.120`** | **91.2%** |

最终采用后者。

### 质量实测

400 个随机常用字，比对源字体与产物的**字怀（内白）**个数与面积：

| 指标 | 拆笔画重画（旧） | 就地推拉（现） |
|---|---|---|
| **字怀保持率** | 12% | **91.0%** |
| 碎裂 | 88% | 5.0% |
| 糊住 | 0% | 4.0% |
| 字怀面积比 | 0.93 | **1.01** |
| 全量构建失败 | 193 字 | **0 字** |

几何校验（`src/check_lishu.py`，2500 字抽样）：零空字形、零越界、零绘制异常。

### 只处理汉字，标点原样保留

标点（`，` `。` `、`）是**小而密**的图形，骨架在内部乱分叉，推拉后会变成巨大的圆圈和黑块。
所以只对 CJK 码位做形变处理，标点 / 拉丁 / 符号**原样保留**。

> 这个 bug 曾让整段排印报废，而**质量指标没抓到**——因为指标只抽样了
> `0x4E00-0x9FA5` 的汉字，标点不在范围内。**是成段排印的目视检验抓出来的。**
> 「指标全绿」不等于「能用」。
